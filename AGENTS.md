# Architecture rules

- Cluster membership (ai, krypto, fintech, startup, investering, daytrading) comes only from `article_clusters`, rebuilt by `rebuild_article_clusters()` using `cluster_seed_nodes` (topic/entity evidence) and `cluster_definitions`. Why: `articles.category` is a broad editorial field, and mapping it straight to clusters gave wrong authority numbers.
- Editorial category can only support a cluster membership, never decide it alone. A membership needs at least one strong topic or entity seed. Why: stops broad categories from inflating clusters.
- Cluster consumers (`compute-authority`, `build-internal-links`, ClusterPage) must read the membership layer or `cluster_membership_stats()`. They must not keep a local category→cluster map. Why: one canonical classification.
- Evergreen generators (`generate-knowledge-pages`, `generate-guides`, `generate-comparisons`) must call `evergreenGuard()` from `_shared/evergreen-guard.ts` before any AI generation and only generate on CREATE_NEW (or UPDATE_EXISTING with explicit `allow_update` on the same slug). Order: slug → mirrored pair → normalized title across tables → pgvector via `evaluateDuplicate()`; if the semantic layer is unavailable the verdict is REVIEW_REQUIRED (fail closed). `dry_run: true` returns verdicts with no writes or generation. Why: slug uniqueness alone let near-identical evergreen pages cannibalize each other.
- All public URLs (canonical, og:url, JSON-LD, sitemaps, RSS) use https://marketrends.no; never the lovable.app host or a backend project ID. Why: one canonical host for SEO.
- News collection supports read-only dry runs and an explicit fetch-only mode; scheduled collection remains fetch-only during credit recovery. Why: repair scheduler authentication without repeatedly calling an exhausted AI provider or restarting bulk generation.
- Public sitemaps are generated at build time by `scripts/generate-sitemaps.mjs` into the build output (served under https://marketrends.no; robots.txt points only at `/sitemap-index.xml`). Backend sitemap functions are internal only. Why: static hosting cannot proxy to backend functions, and backend hosts must never be advertised.
- Cluster pages are canonical at the short vertical URLs (`/ai`, `/krypto`, …); `/cluster/:slug` only redirects there. Why: one URL per cluster.
- Measured search metrics live in private GSC fact tables; page and query datasets must never be summed, and daily refresh revalidates the selected verified property. Why: top-query omissions and dimension overlap make synthetic or mixed totals misleading.
- GSC recommendations and pillar reviews are analysis-only; noAI coverage checks fail closed without a cached semantic input. Why: measurement must never trigger content generation or assert an unverified gap.
- Article internal links reconcile in bounded transactional cursor batches, then a relation-change queue; reference links reconcile separately. Why: full-corpus coverage and stale-link pruning without unbounded function queries.
